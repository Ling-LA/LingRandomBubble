# Ling 随机气泡 0.1.49

通过 QQ 自己的商城接口切换账号装扮，供未安装模块的接收端显示新气泡。0.1.49 改用 QQ 当前 ChatPie 的权威会话链，处理同一 Fragment 留存旧联系人包装导致的逐消息跳过，并核对回复取消后的实际回复状态。管理全部在 QQ 原生面板内完成，独立模块应用可选。本轮 96 核心、92 Android、构建及实机已覆盖旧联系人冲突、取消回复、双击、两次取消保护和冷启动后的原候选池发送。六条正向各一条，用户最新配置已恢复；接收端本轮暂无法配合，样式及重进未验证。具体范围见 [0.1.49 验证报告](docs/VALIDATION-2026-10-02-0.1.49.md)。旧消息属性替换路径保持关闭。

## 使用

1. 将 0.1.49 模块更新到 LSPatch 集成的 QQ 内，再启动 QQ。进入 **QQ → 设置 → 模块 → Ling 随机气泡**，即可在 QQ 内完成管理；无需另装独立模块应用。若保留独立应用，请使用同版本；只安装独立 APK 不会更新 QQ 内嵌模块。
2. 每个新账号先在 QQ 装扮商城正常设置一次自己有权使用的气泡，初始化正常接口。账号已初始化后，重启 QQ 可直接使用，无需每次进入商城。
3. 在 QQ 模块面板打开“气泡库”：支持名称或编号搜索、每页 20 项、只看已勾选、全选全部、取消全选、撤销最近一次批量选择；长按可改名或删除。全选覆盖所有分页及搜索外条目，且不会启动轮换。
4. 将已勾选的主气泡编号填入账号装扮配置；编号会去重，请保留有使用权益的款式。手动切换使用第一个编号；轮换至少需要两款不同气泡。定时和逐消息模式分别启用，默认均关闭，启用须由用户明确保存。
5. 定时模式提供低频 1800 秒、高频 60 秒预设，间隔可自选 60～86400 秒。逐消息模式仅支持原生普通文字的物理发送按钮：点击后先切换装扮，服务器和 QQ 缓存均确认后才恢复这一次发送。请在面板运行状态中核对结果。

气泡库采集的是样式线索，收藏或 SVIP 身份不等于拥有每一个气泡。新编号沿用正常商城参数，仍由服务器核验；若服务器拒绝，可先在商城正常设置该款再试。预检响应有效且款式匹配、但未确认使用权益的候选会被跳过，不提交 SET；同一配置代次内不再自动选它，重新保存配置后可重新核对。逐消息一次等待最多核对三款候选；没有另一款可用气泡时取消恢复并保留输入，提示调整编号。响应结构不匹配、业务拒绝或接口变化仍会暂停，不绕过权益验证。

## 行为与保护

两种模式都修改整个账号的当前装扮，随后发送的消息使用该装扮。逐消息模式增加每次受支持发送点击的商城查询和设置请求，不等待定时模式的 60 秒起配置间隔；单个请求串行执行，查询暂错仍有退避冷却。它不把气泡字段直接写入消息，也不承诺历史消息按发送时的款式永久固定。

逐消息模式最多等待 30 秒恢复发送；超时、输入改动、会话或账号变化、配置改变、后台或锁屏会取消恢复并保留输入框。已经提交的账号装扮设置仍可能完成，但取消的发送不会因晚到回调重新恢复。附件、回复、@、Enter 键及脚本发送走 QQ 原有流程，不宣称这些路径会逐条变换气泡。模块不主动生成新消息；恢复操作只对应用户的一次物理发送点击。

当前会话由 QQ 的 Fragment→ChatPieManager→当前 ChatPie→当前 AIOContext/会话参数确认，并核对 Fragment 当前弱指针和实际发送按钮所在根视图。历史包装只用于定位 Fragment，旧联系人不参与当前会话判定。发送等待期间，当前指针改变、收到新会话参数、隐藏、暂停或销毁视图都会取消恢复；随后返回原会话也不能恢复旧点击。必要观察钩子或当前链无法确认时沿用 QQ 原发送。回复取消后，仅在回复 tag、复合图标及 QQ 只读 GetReplyData 查询都确认为空时视为普通文字；查询未知不延后恢复，不修改 QQ 回复状态。

定时器在 QQ 本机独立每秒检查一次，不依赖气泡库同步完成；同步异常不会停止后续调度。配置间隔限制的是尝试频率；无权益目标被跳过时，下一个目标仍等待配置间隔，所以实际气泡变化可能相隔更久。运行中使用单调时钟，冷启动读回持久化冷却，系统时钟回拨不会令轮换一直等待。仅在 QQ 前台、亮屏且解锁时发起设置，提交前再次检查；后台或锁屏取消尚未提交的操作，回到前台可恢复，不因此永久阻断配置。

QQ 本机的气泡库、勾选和装扮配置按账号保存在 QQ 私有目录，重启后读取。批量收录一次保存，重复内容不反复写盘，库文件使用 AtomicFile 保存。采集、全选、打开面板及配置迁移不会启用轮换；切换账号后请重新打开面板，旧面板不能修改新账号。

独立应用存在时可同步配置；QQ 面板的明确编辑会同步回独立应用，旧响应不会覆盖较新编辑。气泡库 JSON 超过 128 Ki 字符时仅同步装扮控制，气泡库在 QQ 内管理，独立应用不会获得完整大库。来自独立应用的控制在同步失联或距最近成功同步达到 15 秒时暂停；明确保存为 QQ 本机控制后，可独立执行。

手动请求一次消费、30 秒有效。提交前检查权益，设置后复查服务器当前装扮并刷新 QQ 缓存，保留字体；重复回调不重复设置或发送。查询暂错先退避，连续三次才暂停并要求重新保存配置；有效查询会重置暂错计数，无权益候选跳过不会当作网络失败。SET 提交结果不确定时仅做只读核对，不自动重复提交；业务拒绝或未知结果要求用户核对后重新保存。停止模式会阻止后续设置，已提交的操作可能仍会完成。

高频和逐消息都会增加账号设置请求；短时测试不能证明长期风控安全，也不承诺零风险。低频建议仍为 1800 秒，按自己的风险接受程度明确启用。

## 构建与回滚

准备 JDK 17/21、SDK API 35、Build-Tools 35.0.0，运行 Build-Windows.cmd 或 Build-Linux-Mac.sh。中文路径构建启用 android.overridePathCheck=true；Gradle 8.9 由脚本校验后下载。核心测试：tools/test-core.ps1。

Android 安全测试仅验证配置与策略，不能替代 QQ 原生面板和接收端验收。测试期间可临时安装模块及测试 APK；日常集成使用无需独立应用。执行默认测试时先停止 QQ，测试后重启 QQ：

```text
adb shell am force-stop com.tencent.mobileqq
adb shell am instrument -w io.github.ling.randombubble.test/io.github.ling.randombubble.DeviceSafetyInstrumentation
```

测试 APK 仅供验证，无需日常安装。回滚可按现有签名覆盖安装 device-backup/QQ-installed-before.apk；勿卸载 QQ 或清理聊天数据。停止模块不会自动把账号装扮改回旧款，可在商城手动恢复。
