# Ling 随机气泡

## 介绍

Ling 随机气泡是一个 Android QQ 模块，通过 QQ 的商城接口切换账号气泡装扮，让未安装模块的接收端也能看到相应样式。当前版本为 **0.1.55**，已验证环境为 **QQ 9.3.50 / LSPatch 集成加载**，其他 QQ 版本和加载环境需自行验证。

主要功能：

- **气泡切换**：支持手动切换、定时轮换和逐消息切换；定时与逐消息模式可分别开启。
- **商城收录**：打开自动收录后浏览气泡商城或搜索指定款式，自动收录已加载的气泡及商城名称，按主编号去重。
- **气泡库管理**：支持聊天收录、名称补全、改名、删除、分页和批量勾选，按账号保存。
- **名称与编号搜索**：支持多个关键词，使用空格、逗号、顿号或分号分隔，匹配任意一个即可；搜索后的全选与取消覆盖全部匹配页。
- **重复项合并展示**：同一主气泡编号显示为一款，保留原始记录；同名但编号不同的款式仍分开显示。
- **QQ 内嵌管理**：奶白薄荷配色、小方形复选框、整行点击，无需额外安装独立模块应用即可管理。

模块遵循账号原有装扮权益。SVIP 不代表拥有全部气泡，收录和勾选也不会授予使用权限。切换影响整个账号的当前装扮；高频和逐消息模式会增加商城请求，建议先使用低频模式，不承诺长期零风险或历史消息样式永久固定。

## 安装

### 下载与加载

1. 在 [Releases](https://github.com/Ling-LA/LingRandomBubble/releases) 下载模块安装包，例如 `LingRandomBubble-0.1.55-debug.apk`。名称带 `androidTest` 的文件用于开发测试，无需日常安装。
2. 使用 LSPatch 将模块集成到 QQ，安装集成后的 QQ。更新已有集成模块时，也需要重新集成新版本；**单独安装模块 APK 不会替换 QQ 内嵌模块**。更新时保留原签名及应用数据，避免卸载 QQ 或清除聊天记录。
3. 重启 QQ，进入 **QQ → 设置 → 模块 → Ling 随机气泡**。独立模块应用为可选组件；如同时使用，应与内嵌模块保持相同版本。
4. 每个新账号先在 QQ 装扮商城正常设置一次自己有权使用的气泡，初始化商城接口。已初始化账号通常无需每次启动都重复操作。

### 配置气泡

开启模块中的“自动收录”，再前往 QQ 个性装扮商城的“聊天气泡”分类，或使用商城搜索查找想要的款式。新加载的气泡会自动进入库中；列表已有名称会一同保存，重复浏览不重复新增。只收录已加载的数据，不自动翻页；需要更多款式时手动下滑加载。关闭自动收录后停止接收新结果。若页面使用缓存且没有重新加载，可重新搜索或重新进入分类触发加载。

打开“气泡库”，搜索并勾选需要的款式。新收录默认不勾选，也不会自动添加到账号装扮的轮换编号中。名称缺失时会自动排队补全；尚未补全的条目仍可按编号搜索或手动改名。例如搜索 `小昔 2143049`，会显示名称包含“小昔”或编号包含 `2143049` 的结果。长按条目可管理，批量操作仅作用于当前筛选结果。

将需要使用的主气泡编号填入账号装扮配置，保留具有使用权益的款式。手动切换使用第一个编号，轮换至少需要两款不同气泡。勾选、收录和打开面板都不会自动开启轮换，需要明确保存模式配置。

| 模式 | 行为 |
| --- | --- |
| 手动切换 | 按需设置指定气泡 |
| 定时轮换 | 低频预设 1800 秒，高频预设 60 秒，可配置 60～86400 秒 |
| 逐消息切换 | 对受支持的发送按钮点击，先切换并确认装扮，再恢复本次发送 |

逐消息模式适配普通文字、QQ 自带小表情和原生引用回复文字，引用中的原生 @ 随引用处理。图片、收藏表情包、附件、无引用 @、Enter 键及脚本发送沿用 QQ 原有流程，不保证逐条更换气泡。

定时切换仅在 QQ 前台、亮屏且解锁时发起，配置间隔表示尝试频率；候选不可用时，实际样式变化可能更慢。出现异常可先关闭相关模式，并查看模块运行状态。关闭模式不会恢复旧装扮，需要时可在商城手动切回。

## 实现

### 账号装扮切换

模块在 QQ 进程内运行，复用 QQ 商城正常请求与登录认证，先核对气泡权益，再设置账号装扮，并确认服务器结果和 QQ 缓存。当前路径不直接改写消息中的气泡字段。

有效响应中未确认使用权益的候选会被临时跳过，不删除库条目或取消勾选；排除状态限于当前进程、账号和配置代次，重启或重新保存配置后重新核对。接口结构未知、业务拒绝或设置结果不确定时会暂停或只读核对，不绕过权益校验，也不盲目重复提交。

商城设置接口未初始化时，发送直接沿用 QQ 原流程，不拦截消息；在商城正常设置一次有权使用的气泡后可启用切换。切换失败但输入和会话仍一致时，按当前气泡恢复本次原发送一次，并暂缓逐消息切换 60 秒，期间新点击直接发送。

逐消息模式只恢复用户触发的一次发送，最多等待 30 秒。等待期间文本、表情、引用、会话、账号或配置发生变化，以及进入后台或锁屏时，会取消恢复并保留输入。已经提交的装扮设置仍可能完成，取消的发送不会被迟到回调恢复。

### 收录、搜索与名称补全

气泡库按账号保存在 QQ 私有目录，使用原子写入。相同主编号的不同采集属性或子气泡记录仅在展示层合并，原数据保留；合并行的勾选、改名和删除只作用于当前匹配成员。

商城收录被动观察 QQ 已有列表、搜索及详情响应，只接收明确标记为气泡的商品编号和名称；头像挂件、字体和主题不会混入。解析和持久化在有容量限制的后台队列执行，开关变化或切换账号后，旧响应不能继续写入。收录不会发起购买或设置装扮请求。

收录时优先使用商城返回的名称或复用已有商城名称。缺失名称按主编号去重后自动排队，串行读取商城详情；成功请求至少间隔 2 秒，失败后退避重试。查询只在 QQ 前台解锁、接口已初始化且装扮请求空闲时启动，无需保持气泡库面板打开。名称查询不设置账号装扮，不覆盖自定义名称或轮换配置；离线或接口未就绪时不会立即获得名称。

搜索统一匹配商城名称、自定义名称及主/子编号，忽略大小写和全角/半角差异。批量选择使用当前结果的完整快照，包含其他页，避免修改筛选范围之外的记录。大库主要在 QQ 内管理，独立应用不保证同步完整大库。

## 构建

### 环境

- JDK 17 或 21，设置 `JAVA_HOME`。
- Android SDK API 35、Build-Tools 35.0.0，设置 `ANDROID_HOME`。
- 首次构建需要联网下载 Gradle 和依赖。仓库脚本使用 Gradle 8.9，并校验下载包的 SHA-256。

### Windows

在项目根目录运行，或直接双击 `Build-Windows.cmd`：

```powershell
.\Build-Windows.cmd
```

脚本自动查找 JDK 和 Android SDK，执行核心测试、编译和 Android Lint；构建日志保存为 `build.log`。

### Linux / macOS

设置好 `JAVA_HOME`、`ANDROID_HOME`，并将 JDK 的 `bin` 加入 `PATH` 后运行：

```bash
bash Build-Linux-Mac.sh
```

两种入口构建的原始 APK 均位于：

```text
app/build/outputs/apk/debug/app-debug.apk
```

便捷脚本也会将安装包复制到 `out/LingRandomBubble-0.1.55-debug.apk`。版本号以 `app/build.gradle` 为准。

### 测试与其他构建方式

仅运行核心测试：

```powershell
# Windows
powershell -NoProfile -ExecutionPolicy Bypass -File tools/test-core.ps1
```

```bash
# Linux / macOS
bash tools/test-core.sh
```

安装 Gradle 8.9 后，也可直接构建模块、Android 测试 APK 并执行 Lint：

```text
gradle --no-daemon --console=plain -Pandroid.overridePathCheck=true :app:assembleDebug :app:assembleDebugAndroidTest :app:lintDebug
```

Android 实机测试步骤见 [设备测试说明](docs/DEVICE_TESTS.md)。编译成功和自动测试通过不能代替真实 QQ 会话及接收端验证。仓库不提供发布签名密钥，自行构建的 APK 更新既有安装时需要使用一致的签名。
