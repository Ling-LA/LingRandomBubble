## 第一版做了什么

独立应用面板负责：发送总开关、气泡采集开关、随机或固定模式、避免连续重复、群聊/私聊范围、勾选气泡、改名、删除、JSON 导入导出、复制诊断。

气泡采集只保存访问到的消息中的气泡编号及必要属性元数据，不复制正文、发件人、艾特列表或整份消息。新气泡默认不参与随机，最多保留 128 个。不会自动下载任意编号或扫描网上气泡目录。

在 QQ 自己的消息长按菜单里增加「收藏气泡」。点击后只保存气泡编号和属性字段，不保存正文。收藏项会立刻参与发送。不修改 QFun 安装包，也不改它的 +1 图标、点击监听或复读开关。气泡列表不提供远端图片预览。

## 如何回避 QFun 复读

不是简单靠“看起来不像复读”判断。只有以下条件同时成立才会生成新的气泡属性：

1. QQ 版本匹配，发送、转发观察、原消息读取、触摸观察接口均已挂接，配置桥接正常，用户主动开启总开关。
2. 观察到 QQ 输入框旁可识别的“发送 / Send”按钮的按下与抬起，输入框类匹配 AIOEditText。产生 2.5 秒内有效、只能消费一次的许可。许可仅在内存中保存会话加盐摘要。
3. 当前发送的纯文本与点击时输入框文本完全相同；聊天类型是启用范围中的群聊/好友私聊。
4. 发送线程可以是 QQ 内核的异步线程。授权来自刚才那一次发送按钮点击，不要求这个线程上还留着输入框调用栈。QFun、转发和已见过的原消息对象仍然直接跳过。
5. 不是 QFun / 复读 / 转发调用栈，不在同步转发作用域内，也没有复用已访问原消息的列表、元素或属性对象。

`forwardMsg` 只观察进入/退出，用于维护本模块自己的回避标记，**不改其参数或返回值**。对 `sendMsg`，只有所有门控通过后才替换参数中的属性 Map；不更改正文、联系人、消息编号或回调。

`msgAttrs → MsgAttributeInfo → VASMsgElement → bubbleInfo` 采用逐层复制后修改；不原地修改收藏来源或其他模块持有的对象。不撤回重发，不主动调用第二次发送，不更改账号全局气泡，也不修改 `SVIPHandler.getSubBubbleId`。

这些是代码中的防护措施，**不是“已经证明与所有 QFun 版本零冲突”**。未来 QQ 或 QFun 改变路径仍须重测。

## 在 Windows 构建 APK

先准备 **JDK 17 或 21**、Android SDK **API 35**、**Build-Tools 35.0.0**。Android Studio 的 SDK Manager 可以安装这些组件。建议解压到不含中文和空格的路径，例如 `E:\LingRandomBubble`，减少 Windows 工具链路径问题。

然后双击 **`Build-Windows.cmd`**。

脚本会检测 JDK / SDK，首次从 Gradle 官方站下载 Gradle 8.9 并验证固定 SHA-256，运行核心测试，执行 `assembleDebug` 和 `lintDebug`。首次构建还需要下载 Android Gradle Plugin 和 Xposed 编译接口。下载失败或缺少环境时会停止、保留窗口，并将错误写入 `build.log`。不会自动安装应用、修改手机、上传项目或更改系统安全设置。

真正构建成功后，文件才会出现在：

```text
out/LingRandomBubble-0.1.12-debug.apk
out/SHA256SUMS.txt
```

此包没有伪造的 `gradle-wrapper.jar`。脚本使用经校验的 Gradle 发行包直接运行。使用 Android Studio 时，可先执行构建脚本，或在 Gradle 设置中选择 `.tools/gradle-8.9` 作为本地 Gradle。

Linux / macOS：配置 `ANDROID_HOME` 与 JDK 后运行 `bash Build-Linux-Mac.sh`。

### 可选：在自己的 GitHub 仓库构建

工程带有 `.github/workflows/build.yml`。只有你自行上传完整工程并在 Actions 中手动运行 **Build experimental APK** 才会触发构建。本次没有替你创建、上传或修改任何仓库。

工作流产物只在 Android 编译和 Lint 均成功后上传。云端临时 debug 签名可能随每次运行变化；长期迭代宜在同一台电脑保留同一份 debug keystore，或自行配置固定发布签名。**不要把私钥提交到仓库。**

## 构建成功后的安装与初测

**不要卸载 QQ，也不要关闭现有 QFun 来“解决”未适配问题。** 此模块尚未实机验证，首次测试先保持发送总开关关闭。

1. 安装本模块 APK，打开独立面板一次。把模块加载目标设为 **QQ（com.tencent.mobileqq）**，不是 QFun 设置应用。
2. 在当前 NPatch 中，让 QQ 同时加载 QFun 和本模块。本地加载模式通常是在 QQ 的模块管理中添加；集成模式需要重新修补时同时包含两个模块。具体入口随 NPatch 版本不同，按已有成功方案操作，不要直接卸载 QQ。
3. **保持你之前能正常工作的“注入加载器 Dex”关闭状态，不要为了本模块重新打开。** 添加模块后完整结束并重新启动 QQ。
4. 在 QQ 里长按别人一条有气泡的消息，点「收藏气泡」。收藏会写入独立气泡库并默认参与发送，不要求重启 QQ。面板里可以改成固定气泡、取消勾选，或打开“避免连续重复”。
5. 先只勾选一种已采集气泡，打开固定模式与发送总开关。输入一段全新普通文字，点击屏幕上的“发送”。让另一台未安装任何气泡模块的 QQ 检查，退出会话后重新进入再检查。
6. 固定气泡通过后，再勾选多种气泡，关闭固定模式验证随机。最后逐项执行 `docs/DEVICE_TESTS.md` 的 QFun 回避测试。

采集时看不到气泡，或普通发送仍是原样，不要关闭回避规则硬发。复制面板中的诊断，检查各接口、发送点击计数、未知来源跳过计数和模板数。未收到进程报告可能是没有注入或配置桥接未连通。

## 首版范围与已知限制

- 只处理**点击可识别发送按钮的新普通文字**。图片、语音、文件、表情混排、艾特、引用回复、陌生人临时会话、频道、长于 4000 字的文本、键盘回车发送均跳过。
- QQ 的 `sendMsg` 通常在内核异步线程执行，调用栈里没有输入框。0.1.1 起这种情况仍按发送按钮许可替换气泡。没有这次点击、或调用栈属于复读/转发时，仍然不改。
- 若其他脚本在发送前修改了正文，摘要不匹配会跳过。不能同时要求严格匹配且无条件跟随任意脚本改写。
- 固定模式使用库中第一个勾选项。暂不提供拖动排序、每群独立设置或气泡图片预览。
- 删除后仍在同一采集会话内的条目可能不会立即再次采集；关闭再打开采集开关后重新浏览即可。
- 其他模块可能清理或改写气泡属性。首测应避免同时开启另一套随机气泡/强制默认气泡功能；**QFun 的普通复读功能可以保留用于兼容性测试**。
- 收藏到某个样式不等于获得对应会员权益，也不保证服务器会接受。只测试你有权使用的样式；不提供权益解锁、账号风控绕过或服务器权限修改。
- QQ 更新仍可能破坏接口；QFun 更新不会直接覆盖本模块的代码，但不能免除共存测试。

## 隐私与退出

没有登录、广告、统计 SDK 或网络请求代码。独立应用没有申请网络、外部存储、无障碍、悬浮窗或 root 权限。文件导入导出使用 Android 文件选择器。

本模块只通过明确的气泡字段获取样式元数据；诊断记录接口状态、计数，以及必要的类/方法名称，不记录消息正文、联系人编号或 Cookie。设置存放在模块应用私有目录，配置 Provider 会校验调用 UID，仅允许本模块与 QQ 同步。自动备份关闭。

停止使用：关闭发送及采集开关，并在 NPatch 中取消此模块加载；重启 QQ。不需要删除 QFun 或 QQ 聊天数据。气泡库可先导出备份。
