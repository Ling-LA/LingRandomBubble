通过 QQ 自己的商城接口切换账号装扮，供未安装模块的接收端显示新气泡。管理全部在 QQ 原生面板内完成，独立模块应用可选。普通文字、QQ 自带小表情及原生引用回复文字是逐消息模式的适配范围；引用内 QQ 原生 @ 随引用处理，无引用 @、图片消息、表情包图、附件、Enter 或脚本发送仍走 QQ 原流程。0.1.52 R2 完成了下述短时发送、取消及恢复配置验证，接收端重进保持由用户文字确认，详[52报告](docs/VALIDATION-2026-10-03-0.1.52.md)。51现场媒体异常的真实根因仍未知，不宣称已修复。

0.1.51 的引用及普通文字实测、取消保护与接收端文字确认保留在 [51 历史报告](docs/VALIDATION-2026-10-02-0.1.51.md)，50的小表情及49的当前会话链证据保留在各版历史报告。旧结果不代替52验证，旧消息属性替换路径保持关闭。

## 使用

1. 将构建后的 0.1.52 模块更新到 LSPatch 集成的 QQ 内，再启动 QQ。进入 **QQ → 设置 → 模块 → Ling 随机气泡**，即可在 QQ 内完成管理；无需另装独立模块应用。若保留独立应用，请使用同版本；只安装独立 APK 不会更新 QQ 内嵌模块。
2. 每个新账号先在 QQ 装扮商城正常设置一次自己有权使用的气泡，初始化正常接口。账号已初始化后，重启 QQ 可直接使用，无需每次进入商城。
3. 在 QQ 模块面板打开“气泡库”：支持名称或编号搜索、每页 20 项、只看已勾选、全选全部、取消全选、撤销最近一次批量选择；长按可改名或删除。全选覆盖所有分页及搜索外条目，且不会启动轮换。
4. 将已勾选的主气泡编号填入账号装扮配置；编号会去重，请保留有使用权益的款式。手动切换使用第一个编号；轮换至少需要两款不同气泡。定时和逐消息模式分别启用，默认均关闭，启用须由用户明确保存。
5. 定时模式提供低频 1800 秒、高频 60 秒预设，间隔可自选 60～86400 秒。“逐消息切换（文字 / 表情 / 引用）”适配普通文字、QQ 自带小表情及原生引用回复文字的物理发送按钮：点击后先切换装扮，服务器和 QQ 缓存均确认后才恢复这一次发送。引用内 QQ 原生 @ 随引用处理；表情包图、图片消息和无引用 @ 不在此范围。请在面板运行状态中核对结果；小表情加引用的组合尚未51实机验证。

气泡库采集的是样式线索，收藏或 SVIP 身份不等于拥有每一个气泡。新编号沿用正常商城参数，仍由服务器核验；若服务器拒绝，可先在商城正常设置该款再试。预检响应有效且款式匹配、但未确认使用权益的候选会被临时跳过，不提交 SET；排除只保存在当前 QQ 进程的当前账号、配置代次内，重新保存配置或重启 QQ 后重新核对，不删除库条目或改动勾选。这是既有行为，不是52新增修复。逐消息一次等待最多核对三款候选；没有另一款可用气泡时取消恢复并保留输入，提示调整编号。响应结构不匹配、业务拒绝或接口变化仍会暂停，不绕过权益验证。

## 行为与保护

两种模式都修改整个账号的当前装扮，随后发送的消息使用该装扮。逐消息模式增加每次受支持发送点击的商城查询和设置请求，不等待定时模式的 60 秒起配置间隔；单个请求串行执行，查询暂错仍有退避冷却。它不把气泡字段直接写入消息，也不承诺历史消息按发送时的款式永久固定。

逐消息模式最多等待 30 秒恢复发送；超时、文本或表情改动、引用替换或取消、会话或账号变化、配置改变、后台或锁屏会取消恢复并保留输入框。已经提交的账号装扮设置仍可能完成，但取消的发送不会因晚到回调重新恢复。图片消息、表情包图、附件、无引用 @、Enter 键及脚本发送走 QQ 原有流程，不宣称这些路径会逐条变换气泡。模块不主动生成新消息；恢复操作只对应用户的一次物理发送点击。

52在非原生或媒体按钮点击前取消旧的待发送文字点击，保留该按钮的QQ原处理。文字延后须确认当前QQ照片队列为空，或严格确认当前会话尚未注册选图处理器（NO_HANDLER）：真实路由、所有者及注册表身份一致，注册表查询前后均无该处理器，实际查询恰好一次返回null且未调用照片handler。已有处理器返回null或未知结果仍沿用QQ原发送。等待期间队列变化、同路由注册/注销事件或NO_HANDLER状态下当前会话照片面板初始化会永久取消相应旧等待，随后清空或再次无处理器也不能复活旧点击，详[媒体结构](docs/qq-media-schema-0.1.52.txt)。R2已实测选图再清空后旧文字0条且草稿保留；注册/注销任务的单独触发、异常无通知和热补丁路径未独立覆盖，不能把这次可见取消当作某个i hook的独立因果证明。

当前会话由 QQ 的 Fragment→ChatPieManager→当前 ChatPie→当前 AIOContext/会话参数确认，并核对 Fragment 当前弱指针和实际发送按钮所在根视图。历史包装只用于定位 Fragment，旧联系人不参与当前会话判定。发送等待期间，当前指针改变、收到新会话参数、隐藏、暂停或销毁视图都会取消恢复；随后返回原会话也不能恢复旧点击。51 对原生引用同时核对输入框引用 tag、顶部图标和 QQ 只读 GetReplyData，保存引用对象及内容指纹快照；引用设置/清除事件也永久取消旧点击。必要观察钩子、当前链或引用结构无法确认时沿用 QQ 原发送，模块不改写或清除 QQ 引用状态。引用内 @ 的适配仅限已确认原生引用的精确 QQ span，不扩展普通 @。

定时器在 QQ 本机独立每秒检查一次，不依赖气泡库同步完成；同步异常不会停止后续调度。配置间隔限制的是尝试频率；无权益目标被跳过时，下一个目标仍等待配置间隔，所以实际气泡变化可能相隔更久。运行中使用单调时钟，冷启动读回持久化冷却，系统时钟回拨不会令轮换一直等待。仅在 QQ 前台、亮屏且解锁时发起设置，提交前再次检查；后台或锁屏取消尚未提交的操作，回到前台可恢复，不因此永久阻断配置。

QQ 本机的气泡库、勾选和装扮配置按账号保存在 QQ 私有目录，重启后读取。批量收录一次保存，重复内容不反复写盘，库文件使用 AtomicFile 保存。采集、全选、打开面板及配置迁移不会启用轮换；切换账号后请重新打开面板，旧面板不能修改新账号。

独立应用存在时可同步配置；QQ 面板的明确编辑会同步回独立应用，旧响应不会覆盖较新编辑。气泡库 JSON 超过 128 Ki 字符时仅同步装扮控制，气泡库在 QQ 内管理，独立应用不会获得完整大库。来自独立应用的控制在同步失联或距最近成功同步达到 15 秒时暂停；明确保存为 QQ 本机控制后，可独立执行。

手动请求一次消费、30 秒有效。提交前检查权益，设置后复查服务器当前装扮并刷新 QQ 缓存，保留字体；重复回调不重复设置或发送。查询暂错先退避，连续三次才暂停并要求重新保存配置；有效查询会重置暂错计数，无权益候选跳过不会当作网络失败。SET 提交结果不确定时仅做只读核对，不自动重复提交；业务拒绝或未知结果要求用户核对后重新保存。停止模式会阻止后续设置，已提交的操作可能仍会完成。

高频和逐消息都会增加账号设置请求；短时测试不能证明长期风控安全，也不承诺零风险。低频建议仍为 1800 秒，按自己的风险接受程度明确启用。
