# 实现说明与边界

## 组件

`HookEntry` 只在 `com.tencent.mobileqq` 主进程安装观察/发送 Hook。通过 `Application.attach` 取得宿主 ClassLoader，延迟重试少量次数，避免不断扫描全部 DEX。它不加载 QFun 的类，不修补 QFun APK。

`AIOMsgItem.getMsgRecord()` 的返回值用于识别原消息列表、元素和非空属性 Map 的**对象身份**，并在用户开启采集后提取气泡元数据。使用弱引用；不用 equals()，也不持有完整 MsgRecord 作为模板。

`UiTapGate` 观察 `Activity.dispatchTouchEvent`，只认可点击路径上的“发送 / Send”按钮和唯一可见 AIOEditText。不替换按钮监听、不消耗事件、不把长按/复读改造成发送操作。所有非匹配点击会清除旧许可。

`SendPolicy` 是真实生产决策代码，可脱离 Android 测试。它同时检查总开关、接口就绪、聊天类型、普通文字、严格输入组件来源、排除复读、原对象身份和一次性正文许可。任何异常返回“不修改”。

`MsgAttrAdapter` 在全部门控通过后创建新 Map，复制当前属性对象与 VAS 包装对象，只替换新 bubbleInfo 的已验证字段。不修改输入 Map 或原元素列表。当前消息已有的 attrId、字体、挂件、其他业务属性保持不变；没有当前 VAS 属性时才使用采集模板的键/类型/属性编号构造对象。

`ConfigProvider` 在独立模块应用进程中保存配置，按 Binder UID 白名单允许 QQ 同步；QQ 的发送 Hook 不直接做 Binder 请求或磁盘操作。`HostBridge` 的单独工作线程同步不可变配置快照和有限数量的气泡模板。桥接失败时快照退回关闭状态。

`MainActivity` 提供独立面板，不在 QQ 上创建悬浮按钮或修改消息菜单。导入文件限制 256 KB、128 条目，验证后一次提交；导入模板不自动启用。

## QFun 复读回避依据

公开 `RepeatMsg.kt` 显示两条路径：

- `forwardMsg` 传入原消息 ID、联系人和原 msgAttrs。
- `sendMsg` 传入原 elements 与原 msgAttrs。

第一条只增加本模块的同步回避标记，不修改转发参数。第二条可以通过已有对象身份与调用栈识别；即使对象或栈丢失，仍需要新的发送按钮许可和 QQ 输入组件来源。QFun 的 +1 不应产生该许可。

**同步 ThreadLocal 不能自动追踪异步转发子任务**；这里依赖“无新的匹配发送许可”“未知来源跳过”和原对象识别继续回避，而不是宣称 ThreadLocal 已经覆盖全部异步情况。

严格来源白名单是当前实现中的保守假设，需要 QQ 9.3.50 实机确认。发送任务可能因协程丢失输入组件帧，造成正常消息被跳过；此类误跳过比错误改动复读更符合本版目标。诊断会仅记录腾讯类名和方法名用于后续适配。

## 不承诺的事情

- 未从用户的 QQ APK 中验证方法实际实现；公开 qqinterface 文件只是接口线索。
- 未验证采集到的 attrId 在每种气泡上都足够、稳定或必需。
- 未验证服务器会接受任意气泡、字体或付费样式；不实现权益绕过。
- Hook 入口存在不等于每条实际调用都经过该方法。
- 本机参数替换不等于接收端显示成功。
- 独立于 QFun 的 APK 更新，不等于独立于 QQ 内部实现。

## 安全退让

保护开关没有“强制绕过”选项。配置不可达、版本不匹配、输入来源不明、混合消息、失效许可、未知字段、多个冲突 VAS 键等情况全部不修改。代码不调用 `sendMsg` 发出新消息，也不调用撤回、重发、账号设置或网络接口。
