# 0.1.51 实机测试方法

目标环境：Android 16 / 2410DPN6CC / QQ 9.3.50 / LSPatch 1.2 集成模式，保留 QFun 1.3.4 等其他原模块。仅在用户授权的测试会话发送明确测试文字；接收端未安装本模块，由用户文字确认或其发送的接收端截图核对，分别注明证据来源。下文为验证方法，51已执行范围以[51报告](VALIDATION-2026-10-02-0.1.51.md)为准，方法清单不代表全部通过。当前六条正向/一次关闭引用取消已有实测，接收端由用户文字回复“是”确认两款与引用卡片及重进保持，未读取接收端截图；最终实际COLD后的配置和设备恢复已核对。

配置测试：先停止 QQ，临时安装模块和测试 APK，运行 DeviceSafetyInstrumentation 默认操作，隔离账号配置并在 finally 恢复全部偏好，测试后重新打开 QQ。检查 HostSettings 默认关闭、独立定时/逐消息字段、按账号隔离、一次消费、无命令镜像、待确认标记、停止行为及严格验证。增加批量收录去重不写盘、AtomicFile 中断恢复、相同 JSON 不重写、runtime 账号未知不使用历史值的检查。配置测试不代表消息交付成功。

内嵌入口测试：覆盖更新模块并保留 QQ 原数据，首次和重复进入 QQ→设置→模块→Ling 随机气泡，确认原生面板可打开、只一条入口、其他模块入口保留。记录可见 UI 和诊断，不以安装成功或钩子计数判定可用。完全无独立应用时完成库管理、保存配置、手动切换、定时及逐消息测试和重启读回。

库与同步压力测试：使用 1000 项以上库，覆盖搜索、翻页、全选全部、取消全选、撤销、只看已勾选及长按管理；全选不受搜索和分页限制且不启用模式。批量收录和大库保存期间观察独立每秒 tick 心跳持续增长。超过 131,072 字符的库只同步装扮控制，QQ 库不被旧小库覆盖，独立应用完整大库同步不作通过要求；库的待确认标记不得被虚假清除。

独立应用可选测试：覆盖正常存在、临时不可达、完全未安装/不可见三种状态，记录隔离方法并恢复安装状态。小库 QQ 编辑在两个同步周期后仍保留，旧响应不覆盖新编辑；模拟 Binder 同步长期挂起，companion 来源应在最近成功同步满 15 秒后暂停，本机明确保存的控制和独立 tick 应继续。独立应用未实测的项目必须标记未覆盖。

账号和配置代次测试：本机库和装扮按账号持久化；旧账号界面在切换账号后保存被拒绝；不沿用旧收录队列、自动配置或发送恢复。详情/设置回调到达前改配置、停止模式或切换账号，旧回调不得恢复发送或覆盖新代次。公开前遮盖账号及私人会话。

定时测试：初始化商城接口后离开商城，手动切换必须看到权益检查、设置响应、服务器当前装扮确认及缓存刷新。高频至少观察两个真实 60 秒周期，记录实际间隔及心跳，冷启动继续检查；低频 1800 秒检查保存和冷却，未等待完整周期须明确说明。模拟系统时钟回拨或冷启动未来时间戳，确认不会永久等待；大库同步异常后调度仍继续。后台及锁屏在未提交时取消，回前台可恢复且不产生永久 blocked。停止后观察超过高频周期无新 SET，重启仍关闭。

逐消息正向测试：47和48短时发送/接收端与取消保护属于历史结果，不覆盖后来故障，不能作为本次通过。48A/B用户曾确认重进保留，但后续同Fragment/root的两个包装Contact冲突真实复现。仅启用逐消息、定时关闭；使用两款有权益气泡，在用户授权的测试会话通过原生普通文字物理发送按钮发送唯一标记，记录权益检查、SET、服务器及缓存确认、原按钮恢复和计数，核对无重复及本轮接收端样式。该模式增加每次点击的商城请求，不等待定时模式的配置间隔，不能用定时成功代替逐消息测试。

生命周期保护回归：等待期间触发当前指针变更、新会话参数onNewIntent、隐藏、暂停或销毁视图，然后返回原群。原点击须永久取消且草稿保留，即使最终pie/context/param身份恢复也不恢复旧点击。分别记录实际UI动作与消息数；仅核心身份fixture通过不能证明中间事件被真实hook观察。必要hook注册部分失败时应保留QQ原发送，ready不得提前发布；没有实际故障注入不记这一分支实机PASS。

51引用正向与取消回归方法：从QQ原生引用操作进入回复，分别测试引用回复文字、带QQ小表情的引用文字，以及引用内QQ原生@。先记录tag/顶部Drawable/GetReplyData一致及服务器/缓存确认，再核对恢复一次、可见一条、引用对象/内容保留，不只看“已延后”。同款点击快速双击仍最多一条。等待期间替换引用、取消后重新引用原消息、修改后还原输入及离开/返回会话，应永久取消旧点击并保留草稿；分别记录0条消息和当前引用状态。普通无引用@应沿用原QQ路径，不以引用@通过扩展普通@。本轮已测引用文字/引用内QQ原生成员选择@、双击和关闭预览X的逻辑清除；没有测小表情加引用、引用回切、h.m重绘或普通无引用@现场分支，不将整段方法记PASS。

取消引用后的普通文字回归：QQ tag、复合图标及GetReplyData逻辑回复须确认为空，即使aio.reply.a movement残留也可适配。当前原生引用仅在ReplyStateGate完整结构及快照可确认时延后；查询未知、结构不一致、缺失tag资源、未知预览或未齐必要设置/清除hook时沿用原QQ，等待期间出现这些变化则取消恢复。模块不得清空输入、tag、图标、movement或逻辑回复。fixture覆盖身份/字段变化，不代替真实QQ写入hook、双击与消息交付验证。

逐消息取消与失败测试：延后期间修改再恢复输入、替换/取消引用、改变会话、退后台、锁屏、改变配置或账号，均取消恢复并保留输入。慢响应超过 30 秒只取消发送恢复，已提交操作仍可在 65 秒看门狗内完成只读核对，晚到回调不得重新发送。重复点击、重复 API 回调、恢复回调抛异常不得产生重复恢复。查询暂错后再次点击不得绕过退避；连续三次暂错才暂停，有效查询穿插时须重置计数。预检响应有效但无权益的目标不应产生 SET，应在当前配置内跳过；逐消息最多核对三款，候选耗尽须取消恢复，保存新 generation 后允许重新核对。SET 响应未知仅追加只读详情，不能自动重复 SET。图片消息、表情包图、附件、无引用@、Enter 和脚本发送沿用 QQ 原流程，不宣称这些路径逐条换气泡。
