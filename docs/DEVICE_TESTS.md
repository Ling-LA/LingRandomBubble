# 真机验收：QQ 9.3.50 + QFun 1.3.4

状态：**下列用例尚未执行**。测试时接收端应使用未安装气泡模块的 QQ；本机看到变化不足以证明发送成功。

先备份模块气泡库，保留现有 QQ 的正常工作配置。不要删除 QQ 数据。建议使用测试会话，避免反复刷消息。不要在含私密内容的会话中截图反馈。

| 测试 | 步骤 | 预期 |
|---|---|---|
| 关闭状态 | 关闭本模块发送开关，正常发一条新文字 | 原行为不变，不多发、不丢失 |
| 接口与桥接 | 打开独立面板“查看诊断” | QQ 版本正确，各接口为 true；收到新的进程报告 |
| 模板采集 | 仅开采集开关，浏览几条有气泡的消息 | 库出现未勾选的新模板；不自动启用发送 |
| 固定气泡 | 只选一个模板，固定模式，点击发送全新文字 | 正文与收件人不变；仅一条消息；接收端核对气泡 |
| 随机气泡 | 选择两个已验证模板，随机模式，连续发三条不同文字 | 接收端气泡按有效模板变化；不连续重复 |
| QFun +1 普通复读 | 本模块开启时点击别人的 +1 | 保留 QFun 的原始复读内容及气泡；本模块不换样式 |
| QFun +1 艾特复读 | 复读含真实艾特的消息 | 艾特对象/内容/气泡保留；不触发本模块替换 |
| 收藏气泡 | 长按别人一条有气泡的消息，点「收藏气泡」 | 只增加本模块按钮；库中出现该气泡并默认参与发送；不保存正文 |
| QFun 长按复读 | 将 QFun 设为长按复读并复读消息 | 复读仍用原气泡；本模块不改 QFun 的 +1 和复读菜单项 |
| 有输入草稿时复读 | 输入但不发送文字，然后点别人 +1 | 原草稿不变；复读原样；不误用随机气泡 |
| 极短间隔 | 正常发送后立刻点另一条消息 +1 | 原来的许可最多消费一次；复读保留原样 |
| 转发 | 原生转发一条消息到测试会话 | 转发的内容/气泡保持原逻辑；不额外发送 |
| 同文不同来源 | 输入框中键入与别人消息相同的文字，但先点 +1 | 相同正文不应被当成自己按发送；复读原样 |
| 自动回复 | QFun 脚本触发自动回复，但没有点击发送 | 本模块不应用气泡；不影响脚本运行 |
| 非普通文本 | 图片、语音、文件、艾特、引用回复、表情混排 | 第一版全部跳过，原功能不受影响 |
| 键盘发送 | 用输入法发送键或硬件回车 | 第一版跳过；只支持屏幕上匹配到的发送按钮 |
| 快速切换会话 | 输入后切换会话，执行复读或自动回复 | 旧许可不得用于新操作 |
| 改开关 | 关闭开关，等约 3 秒再发消息 | 不再修改发送属性 |
| 冷启动 | 完全结束 QQ 后重启 | 状态重新建立，气泡库保留，未持有旧发送许可 |
| 导入导出 | 导出、清空、导入同一库 | 元数据一致；导入后总开关关闭，新条目不自动选中 |
| 升级目标不匹配 | 在非目标版本做受控验证（不是首次测试所必需） | 版本门控阻止发送属性修改 |

## 失败时记录

保留“诊断”文本、QQ 完整版本号、QFun 版本、NPatch 版本与模式。诊断中的计数只是本机行为，不是服务器收据。

- `有效发送点击=0`：可能没有识别到发送按钮 / 输入框，或某个保护接口尚未挂接。
- `已替换发送参数=0` 且 `有效发送点击=0`：没有识别到发送按钮，或总开关/版本/接口未就绪。
- `有效发送点击>0` 但 `已替换发送参数=0`：点击后的那次发送没有对上正文，或被复读/转发/原对象规则跳过。
- `原消息访问次数>0` 但模板数为零：样式是默认气泡、数据结构不匹配，或其他模块清理了属性。
- `已替换发送参数>0` 但接收端不变：可能被后续发送环节或服务端覆盖，也可能模板需要更多经验证的气泡字段。
- **只要出现重复消息、收件人错误、QFun 复读样式被改动，就停止测试并禁用本模块。不要用关闭保护规则作为补救。**

后续修复应针对实际日志和目标版本接口，不应凭猜测扩大白名单或复制整个 MsgRecord。
